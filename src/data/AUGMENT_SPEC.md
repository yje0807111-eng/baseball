# 증강 규칙

증강은 `src/KboAugmentDraft.jsx` 의 `PASSIVE_AUGMENTS`(효과형 81) + 발동형 9 = **등급마다 30개, 모두 90개**.
`scripts/augment-count.test.mjs` 가 개수와 id 중복을 지킨다.

읽는 사람은 경기 도중 3초 안에 고른다. **한 장은 한 가지 일만 하고, 설명은 한 줄로 끝난다.**

## 1. 설명 문법

`desc` 는 아래 토막을 ` · ` 로 이은 한 줄. **두 토막, 많아야 세 토막.**

| 토막 | 뜻 | 보기 |
|---|---|---|
| `타자 파워 +6` | 능력치 증감 (`roster`) | 대상 · 능력치 · 부호 · 정수 |
| `공격 +0.3` | 우리 공격 반 이닝 기대 득점 (`half.add`, myOff) | |
| `실점 −0.3` | 상대 공격 반 이닝 기대 득점 (`half.add`, oppOff) | |
| `공격 ×2` | 기대 득점 배수 (`half.mul`) | |
| `투구 +10` | 그 반 이닝 마운드 투수 보정 (`half.pitch`) | |
| `… 확률로 +1점` | 이닝 점수 보정 (`runs`) | |
| `선발은 4회까지` | 투수 운용 (`team.usage`) | |

조건은 토막 앞에 붙인다 — `9회 수비 투구 +10`, `7회부터 2점 차 이내면 공격 +0.3 · 투구 +6`.

**"모든" 은 쓰지 않는다** — `모든 타자 파워 +8` 이 아니라 `타자 파워 +8`, `선발 모든 능력치 +4` 가 아니라
`선발 능력치 +4`. 같은 대상의 능력치를 여럿 올릴 때는 수치를 각각 붙여 쉼표로 잇는다 —
`좌타자 컨택 +10, 파워 +10`. ` · ` 는 성격이 다른 토막 사이에만 쓴다.

조건도 짧게 줄인다 — `이상` 은 `+` 로(`종합 88+`, `국가대표 3명+ 면`), `… 확률로` 는 `…로`
(`득점한 이닝 20%로 +1점`), `대신` · `우리` · `이번 시즌` 같은 군더더기는 뺀다. 확정은 `확정` 없이
`그 이닝 무실점`, `그 이닝 4점` 으로 적는다.

### 지킬 것

- **소수점 능력치 금지.** `+1.5`, `×0.4` 같은 값은 쓰지 않는다. 기대 득점만 0.05 단위 소수를 쓴다.
- **"차이의 몇 %" 금지.** `(상대 평균 − 우리 평균) × 0.012` 같은 식은 읽는 순간 포기하게 된다.
  비교가 필요하면 **참 · 거짓 한 줄**로 — `우리 주루 평균이 상대보다 높으면 공격 +0.25`.
- **1명당 누적은 예외적으로만.** 그 장의 주제가 머릿수일 때만 쓰고(`좌완 군단`, `레전드의 무게`),
  `1명당 정수 (최대 N)` 꼴만 허용한다.
- **기준선은 70 · 75 · 80 · 85 · 88 · 90 중 하나.** 그 외 숫자를 새로 만들지 않는다.
- **죽은 장 금지.** 어떤 팀이 뽑아도 0이 되는 조건(특정 시너지 필수 등)은 쓰지 않는다.

## 2. 등급별 세기

한 장만 들고 AI 올스타와 붙었을 때 **경기당 득실차 변화(평균)** 로 잰다.

| 등급 | 목표 | 허용 폭 | 지금 (N=800) |
|---|---|---|---|
| 실버 | +0.4 | +0.2 ~ +0.6 | 0.25 ~ 0.56 (평균 0.41) |
| 골드 | +0.8 | +0.5 ~ +1.1 | 0.59 ~ 0.94 (평균 0.77) |
| 프리즘 | +1.4 | +1.0 ~ +1.9 | 1.12 ~ 1.80 (평균 1.38) |

`extreme` 은 성향별 폭이 넓어도 된다 — 대신 **평균은 같은 등급 안에 있어야** 한다.
어느 팀에서도 마이너스만 나오는 장은 고칠 것.

**접전에서만 일하는 장은 득실차로 재지 말 것.** `지옥에 가더라도 데려온다` 는 득실차
+0.82 로 프리즘 바닥이지만 승률은 +17~40 %p 로 90종 중 가장 높다 — 점수 차를 벌리는
대신 질 뻔한 경기를 이기기 때문이다. 끝내기 본능 · 대역전 드라마 · 승부처의 신도 같다.
이런 장은 **괄호 안 승률로 본다**.

### 재는 법

```
BALANCE=1 N=500 npx vitest run scripts/augment-balance.test.mjs
```

성향 여섯(거포 · 발야구 · 투수왕국 · 스타군단 · 레전드 · 균형)마다 N경기씩.
N이 작으면 난수 흐름이 갈려 ±0.3 은 그냥 흔들린다 — **결론은 N=500 이상에서만** 낸다.
결과는 `balance-report.txt`(`OUT=` 로 바꿀 수 있음).

## 3. 종류(`type`)

증강 화면에서 묶는 기준. 한 장에 하나만.

| 값 | 뜻 |
|---|---|
| `build` | 뽑은 선수 구성이 좋을수록 커진다 |
| `play` | 경기 운영(투수 운용 · 승부처)을 바꾼다 |
| `balance` | 약한 곳을 메운다 |
| `extreme` | 한쪽에 몰아주고 다른 쪽을 내준다 |
| `luck` | 운에 맡긴다 |

## 4. 훅

| 키 | 시점 | 돌려주는 값 |
|---|---|---|
| `roster(r, env)` | 팀을 만들 때 | 새 로스터 (`bump` 으로) |
| `team(t, env)` | 로스터 다음 | 없음 — `t.bonus` · `t.weights` · `t.defCoef` · `t.usage` 를 고침 |
| `half(c, st)` | 반 이닝 시작 | `{ add, mul, pitch }` 또는 `null` |
| `runs(c, runs, st)` | 반 이닝 끝 | 점수 또는 `{ runs, text }` |
| `after(c, runs, st)` | 점수 확정 뒤 | 없음 — `st` 에 쌓는다 |
| `flag` | — | `posFree` · `synCopy` |

`c.isTop` 은 상대 공격. 편하게 `myOff(c)` · `oppOff(c)` 를 쓴다.
`st` 는 그 경기 동안 그 증강만 쓰는 저장소다.

발동형은 `when(c)` · `chance` · `max` · `apply(c)` 로, 그 이닝 점수를 **아예 확정**한다
(이때 효과형의 `runs` 훅은 건너뛴다). 조건 `cond` 도 한 줄.
